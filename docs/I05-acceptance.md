# I05 #8 — 검수 조건 제안

## 2026-11-06 사용자 확정 변경 — 이전 조건보다 우선

- 개발·검수 기준은 웹이다. 앱은 후속 검토이며 필요 시 하이브리드 포장을 검토한다. 앱 구현·실측·스토어 결정은 현재 M1 선행 조건이 아니다.
- 현재는 그래픽 품질을 우선한다. 저사양 모바일 최적화·실기기 통과는 후속 검증으로 이연하며 현재 M1을 차단하지 않는다. 웹에서 측정 가능한 성능 기록은 계속 보존한다.
- 사찰 배치는 기존 기획서 구조를 따른다. 배치된 모든 건축 구조물은 출입할 수 있어야 하며 실내가 있는 건물에는 탐방 가능한 내부를 포함한다. 문·누각은 통과/진입 가능한 구조로 구현한다. 석탑 등 내부 공간이 없는 조형물의 인위적 실내를 뜻하지 않는다.
- 전체 배치·실내 제작은 기존 M2 공간 제작 Issue에서 수행한다. M1 샘플을 전체 맵 완성으로 간주하지 않는다. 실행 데이터의 임시 치수·좌표가 원본 기획서를 대체하지 않는다.
- 시각 품질은 사용자가 실제 화면을 본 후 판단한다. 기존 캡처는 검증용 초안이며 승인된 최종 품질이 아니다.


상태: **제안 / 최저 모바일 기기 미정**. PC 측정과 모바일 화면 검사는 실제 모바일 통과 증거가 아니다. 모든 수치는 기존 기능정의서의 승인 제안이며 이번 작업으로 확정되지 않는다.

- PC 목표 평균 60FPS, 1% low 45FPS / 모바일 평균 30FPS, 1% low 24FPS 제안.
- PC 연등 1000개, 모바일 300·500개 제안. 표시 수·실제 시야·해상도·그림자·glow·브라우저·전원·온도 조건 기록.
- 초기 15초 / 재방문 5초 제안, 20Mbps·RTT 80ms. 현재 localhost 결과와 구분.
- 2분 예열→5분 동선 3회, 모바일 20분 지속 실행 후 반복. JS heap과 GPU·프로세스 전체 메모리는 따로 측정해야 하며 제품별 예산은 미정.
- 식별: 5·20·50m 또는 승인 최장 시야, 5명 중 4명 3초 이내 제안. 평가자·판정은 아직 미수행.
- V01~V06 카메라·시간대·품질·화면·빌드 고정. 질감·단청·기와·연등의 세부가 과노출/가림 없이 보이는지 확인. 최저 품질에서도 내 상품 기본 강조 유지.
- 메뉴 키보드 접근·초점 복귀·ESC, 본문 16 CSS px와 터치 44×44 CSS px 제안. 현재 M1은 3D 탐방 전체의 접근성 인증 대상이 아니다.

합격 규칙: 같은 빌드/밀도/설정에서 시각 평가와 성능이 동시 통과해야 한다. 실패를 피하기 위한 임의 밀도·화질 하향 금지. 기준 변경 시 이전 측정 무효, 변경된 조건으로 재측정.
기록 스키마: 장면 버전, 최종 commit SHA(리뷰 기록에 결합), 기기/OS/브라우저, 렌더 크기, 시야/설정, 네트워크/캐시 조건, 프레임 통계, 메모리 의미, 캡처, 승인자·일자·판정. 실측 자료의 raw JSON과 해석을 함께 보존.
