# 모바일 리소스 후속 최적화 구현

2026-11-20. 사용자가 승인한 다섯 항목을 기존 M4 / Epic #1·#4·#74 / Implementation #64·#77의 후속 범위로 구현했다. 새 Issue·목표 날짜를 만들거나 기존 번호·승인 상태를 바꾸지 않았다. 가격·결제는 변경하지 않았다.

## 구현

1. **모바일 건축 모델의 거리별 표현.** 조밀한 불상 몸체·지붕·장식 묶음에 원거리용 단순 모델을 만든다. 카메라가 가까워지면 원래 정밀 geometry를 복원하고, 멀어진 정밀 GPU 자원은 15초 뒤 해제한다. 모델이 통째로 사라지는 방식은 아니다. 재질 묶음의 공간 분할 기준도 조정했다. PC 분기에는 적용하지 않는다.
2. **가상 방문객의 관절별 묶음.** 가까운 외형은 그대로 두고 원거리에는 색상을 정점에 담은 관절별 표면을 사용한다. 한 actor의 검사에서 가까운 표시 부품 53개가 원거리에서 12개로 줄고 접근 후 53개로 복구됐다. 인원·걷기·참배·휴식 루프를 유지한다. 실제 방문객·12지신·스님 외형은 이 묶음의 적용 대상이 아니다.
3. **상태별 렌더 예산.** 기본 모바일 이동·절하기 20fps를 유지한다. 45초 무입력은 15→8fps, 명상은 20→15fps로 바꿨다. 지도·전체 메뉴 중 렌더 중지는 유지한다. 높은 모바일 품질의 무입력은 12fps다. 조작 및 수행 종료에 따라 원래 상태로 복귀한다. 온도 센서를 사용하는 기능은 아니다.
4. **그림자·반사·번짐 예산.** 먼 불상 얼굴은 정밀 그림자에서 제외한다. 무입력 중 그림자 갱신 간격을 늘리고, 카메라가 멈춘 연못 반사는 한 번 그린 결과를 재사용한다. 카메라 이동·시간대·품질 변경에 다시 갱신한다. 기본 모바일 연등 번짐용 화면은 512→256px로 줄이며 연등 자체와 PC 설정을 유지한다.
5. **정밀 얼굴의 준비 분산.** 불상·수호상 정밀 얼굴 9개는 입장 전에 모두 만들지 않고 낮은 밀도로 준비한다. 접근 시 한 프레임에 한 개씩 정밀 모델을 만들며 원본 형상을 사용한다. 정밀 얼굴은 53,984정점, 초기 표면은 3,416정점이었다. 일반 준비 작업도 모바일에서는 약 5ms마다 입력 처리에 양보하도록 했다. 모든 건물의 생성이나 모든 자산 다운로드를 구역 스트리밍으로 바꾼 것은 아니다. 기본 건축 구조와 정밀 건축 복원을 위한 CPU 데이터는 계속 준비·보존한다.

## 검수 중 발견하고 함께 고친 병합 오류

Babylon의 disposed-source 병합은 첫 원본의 인덱스 배열을 제자리에서 늘릴 수 있다. 같은 geometry를 공유하는 전각 복제본이 남아 있으면 나중 구역의 병합에 변형된 배열이 들어간다. 기존 공개 v58의 지붕에서 범위 초과 인덱스를 재현했고, 분할 구역을 늘린 첫 시안에서는 목재에서도 재현했다. 모바일 병합의 첫 원본을 고유 geometry로 분리해 다른 복제본의 배열을 보존했다. NullEngine 회귀 검사와 실제 브라우저의 모든 subMesh 인덱스 범위 검사를 추가했다. PC 병합은 기존 분기를 유지한다.

원시 `getTotalIndices`는 공유 버퍼 전체를 포함할 수 있으므로 모델별 조사에서는 실제 subMesh 범위를 구분했다. 그리기 호출·엔진 인덱스 통계는 실제 GPU 시간·전력·기기 온도 측정값이 아니다.

## 완료된 검증

- 정식 저장소 135개, 체험판 74개 단위 검사와 두 빌드 통과.
- PC 건축·지형 geometry, 색상, 생성 텍스처 픽셀 및 해상도 비교 통과. PC 캐릭터·스님·가상 방문객의 geometry·색상·부착 상태 비교 통과.
- WebKit·Chrome 모바일 조건에서 거리별 건축·불상 복구, 원거리 방문객 묶음과 접근 복구, 화면 회전·지도 터치, 8fps 무입력→20fps 조작 복귀, 15fps 명상→20fps 복귀 검사 통과. 범위 초과 subMesh 인덱스 0개.
- 자동 108배 반복·일시정지·타이머 정지·계속하기·취소·108회 경계 검사 통과. 경계 검사는 107회부터 시작하는 시험 응답을 사용했고 실제 반복 검사는 별도로 수행했다.
- 독립 브라우저 3개의 Colyseus 참가, 상대 캐릭터·이동·외형·참배 전파, 개인방 격리·복귀, 오프라인 제거·재접속 검사 통과.
- 최종 소스를 고정한 WebKit 모바일 일반 애니메이션에서 지도 빠른 열기 20회, 터치 걷기→지도→메뉴를 20회 반복하는 약 619초 연속 검사 통과. 재로딩·page crash·WebGL 손실 0회. 걷기 약 20fps, 지도·메뉴 0프레임. 시작 시 기록한 소스 해시와 배포 준비 시 해시가 같은지도 확인했다.
- 조이스틱 이동·해제·핀치·화면 회전·개인방 터치 이동·복귀 검사 통과. 개인방의 여섯 풍경 전환 후 연못 메시 수는 87개로 돌아왔고, 퇴장 후 engine 장면 수는 1개였다.

## 정밀 복구의 표시 범위 검증

첫 시안에서는 정밀 geometry의 정점 수가 복구되어도 기존 저밀도 subMesh의 작은 표시 범위가 남아 일부만 그려졌다. 전각 실내의 전후 화면 비교에서 이 문제를 발견했다. geometry 전환마다 subMesh 범위를 전체 geometry로 다시 구성하도록 수정했고, 저밀도→정밀→저밀도의 실제 표시 인덱스 수를 검사하는 회귀 검사를 추가했다. 약사전 실내를 다시 촬영해 원래 불상 형상과 전체 표시를 확인했다. 이 문제를 발견하기 전의 부하 측정은 최종 검수 근거에서 제외한다.

## 측정 해석

같은 카메라·기본 모바일 품질에서 공개 v58과 최종 변경판을 비교했다. 실제 참가 인원을 1명으로 격리한 `verified-memory/`에서 JS heap은 강제 GC 후 303,649,412→292,188,316바이트(약 3.8% 감소), scene에 준비된 geometry 정점은 약 280.3만→168.3만이었다. JS heap은 GPU 메모리를 포함한 전체 기기 메모리나 최고 사용량이 아니다. 초기 준비 및 첫 5초의 50ms 이상 긴 작업은 14→13개, 최장 작업은 206→214ms였다. 최장 작업의 개선은 확인하지 못했다. 중간 시안의 1,251→326ms 표본은 최종 개선 근거로 사용하지 않는다. Mac·브라우저 준비 상태와 병렬 검사 영향을 받는 관찰값이다.

부하·긴 작업·장시간 검사 원본은 `evidence/mobile-resource-reduction/`에 보존한다. 중간 실험과 최종 검사를 구별하며, 실패했던 중간 모델 범위 검사를 통과 기록으로 바꾸지 않는다. 실제 iPhone의 발열·배터리 소비·iOS 메모리 한도는 측정하지 않았다. 이번 최적화를 발열 해결이나 특정 온도 감소율로 표현하지 않는다.

최종 정밀 표시 복구 후의 중앙마당 표본은 낮 약 486.5회, 밤 약 496.3회 그리기 호출이었다. 같은 카메라·1명 실제 사용자/19명 가상 방문객의 공개 v58 표본은 각각 약 560.2/570회로, 호출 수는 약 13% 줄었다. 이는 발열 감소율이 아니다. 동일 절전 단계 0과 280×471 출력으로 맞춘 CPU 장면 처리 표본은 낮 6.03→5.85ms, 밤 6.33→6.95ms였다. 밤 CPU 표본은 증가했으며 호출 수 감소를 CPU·GPU 전체 성능 개선으로 일반화하지 않는다. Mac·병렬 실행 영향을 받아 기기 성능 보장으로 사용하지 않는다.

최종 비교는 `fixed-before/`, `fixed-after/`다. 낮/밤 전환 전에 동일한 가벼움 품질을 재선택해 자동 절전 단계가 둘 다 0인지 확인했다. 이전 `release-comparison-after/`의 밤 표본은 자동 절전 단계 1로 바뀌어 출력 크기가 달랐으므로 동일 품질의 전후 비교에서 제외했다.

거리별 GPU 캐시도 별도로 검증했다. 약사전 접근→먼 카메라로 이동→17.5초 대기를 두 번 반복했다. 먼 상태의 정밀 얼굴은 0개로 돌아왔고, 건축 정밀 캐시는 현재 가까운 두 그룹만 남았다. 두 번의 먼 상태 모두 scene geometry 수가 1,786개로 같아 이 경로에서 반복 증가가 없었다. CPU 정밀 건축 데이터의 보존 정책과 전체 메모리 누수 부재까지 증명하는 검사는 아니다.

## 배포 및 공개 확인

체험판 59버전 배포 성공. 소스 SHA는 `0965c523baeb248a0b2081695b3ba9c8119dd707`이다. Mac 공유 서버의 정적 파일도 같은 빌드로 반영했으며 Colyseus 프로세스·주소를 재시작하거나 바꾸지 않았다.

공개 주소에서 WebKit·Chrome 모바일 통합 검사 모두 통과했다. 두 엔진 모두 원거리 얼굴 3,416정점/20,160인덱스에서 근거리 53,984정점/322,560인덱스로 전체 표시 복구, 방문객 53→12→53개 부품, 8fps 절전→20fps 조작·15fps 명상→20fps 복귀를 확인했다. 잘린 subMesh·범위 초과 인덱스는 0개였다. 기존 WebKit WebSocket 생성자 fallback 진단은 별도로 보존했다. `published/`와 `publication.json`에 결과가 있다.
