# iPhone Safari 입장 부하 보완

2026-11-20. 사용자 보고: iPhone 14 Pro Safari에서 입장 로딩 중 발열과 멈춤. 기존 M4 / Epic #1·#4·#74의 Implementation #64·#77 최적화 후속이다. 구현·검수 예상 작업량 S, 브라우저 대기 및 실제 기기 확인은 별도다. 새 Issue나 목표 날짜를 만들지 않는다. PC 그래픽·기존 기능·가격·결제 정책은 유지한다.

## 관찰과 한계

기존 v55는 언어 선택 화면에서 이미 전체 사찰 장면을 생성했고 모바일 렌더링에도 프레임 상한이 없었다. 모바일에서도 최초 엔진은 MSAA와 2048 그림자 대상으로 시작했으며, 저장된 가벼운 설정은 최초 장면 준비 이후 활성화 단계에서 적용했다. 모바일 건물 병합 하나의 최대 크기는 397,920 정점이었다. 이들은 기기 부하를 높일 수 있는 코드상 요인이다. 실제 iPhone의 온도·메모리·Safari 종료 로그는 수집하지 못했으므로 기기 멈춤의 유일한 원인이라고 단정하지 않는다.

## 수정 및 완료 조건

- 모바일에서 입장 버튼을 누른 뒤에만 main 모듈과 3D 장면을 생성한다. PC의 기존 사전 준비는 유지한다.
- coarse pointer를 기준으로 모바일 프로필을 판별한다. WebKit의 휴대폰 모의에서는 coarse pointer지만 maxTouchPoints가 0으로 보고되어 이전의 이중 조건으로 PC 프로필을 적용하는 현상도 관찰했다. 이는 실제 iPhone의 동일 현상을 입증하는 자료는 아니다.
- 모바일은 엔진 시작부터 저장된 품질의 렌더 크기·그림자 크기를 적용한다. 모바일 MSAA를 끄고 low-power 힌트를 사용하며 프레임 상한은 30fps다. 모바일 그림자 필터와 갱신 빈도를 낮춘다. 건물·불상·아이템 모델, 텍스처 해상도·색상 및 PC 설정은 유지한다. 모바일 윤곽과 그림자 표현에는 차이가 있을 수 있다.
- 모바일 건물 병합은 대략 65,536 정점 단위로 나눠 동시에 확장하는 임시 배열의 크기를 줄인다. 한 원본 메시가 이를 넘으면 원본 자체는 유지한다. 화면 요소를 삭제하거나 그래픽 텍스처를 낮추지 않는다.
- 로딩 중 그래픽 연결이 끊어지면 다음 준비 지점에서 작업을 중단하고 엔진을 해제한다. 다시 불러오면 모바일 가벼운 설정으로 준비한다.
- Safari가 페이지를 종료해 예외를 전달하지 못하는 경우를 위해 미완료 입장 표시를 남긴다. 다음 입장 시 가벼운 설정을 적용하고 성공 시 표시를 제거한다.

## 검증

기존/수정본을 Mac의 WebKit 및 Chrome, iPhone 14 Pro 화면·터치 모의에서 비교했다. 기존은 언어 화면에서 canvas와 엔진이 생성되어 있었고 수정본은 둘 다 생성되지 않았다. 각 엔진의 수정본 연속 3회 입장 성공, 6초 동안 렌더링 180회(30fps), 기존은 약 360회(60fps)였다. 수정본 입장 버튼 이후 첫 입장은 이 실행에서 WebKit 약 5.6초, Chrome 약 6.9초였으나 병렬 검사 중의 Mac 수치이며 실제 휴대폰 성능을 보장하지 않는다. 입장 전 생성을 미루므로 버튼 이후 대기와 페이지 전체 준비 시간을 혼동하지 않는다.

두 엔진에서 모바일 건물 총 정점 2,585,130개는 유지되고 병합 메시 최대 정점은 397,920→65,501로 감소했다. 이것은 병합 단위 측정이며 실제 RAM 사용량/발열이 같은 비율로 줄었다는 주장은 아니다. PC의 기존 건물·지형 geometry와 재질·생성 텍스처 픽셀/해상도는 v55와 정확히 일치한다.

그래픽 연결 강제 중단→재시도 버튼→가벼운 설정 입장, 미완료 입장 표시→가벼운 설정→완료 표시 제거를 검사한다. 기존 조이스틱·줌·개인 공간과 PC 품질 회귀 검사도 수행한다. 단위 검사는 원본 121개, 체험판 60개를 통과했다. 결과는 `evidence/mobile-thermal/`에 보관한다.

WebKit 실행 시 기존 Colyseus SDK가 브라우저에서 Node 전용 WebSocket 생성 형식을 먼저 시도하는 과정의 `Wrong protocol for WebSocket '[object Object]'` 진단이 기록되었다. 이후 브라우저 형식으로 재시도해 온라인 배지까지 연결되는 것을 확인했다. 이 진단은 별도 배열로 원시 결과에 남기며, 새 페이지 오류가 없는 것으로 숨기거나 Safari 멈춤 원인으로 단정하지 않는다. 이번 범위에서 SDK나 서버 프로토콜을 변경하지 않았다.

실제 iPhone 14 Pro의 온도 센서, 메모리 압박·강제 종료 및 장시간 발열은 미검수다. 체험판 반영 후 사용자 기기에서 재입장 확인이 필요하다.

최종 로컬 검수: 체험판 전용 초기화를 보존한 소스로 WebKit·Chrome 각각 연속 3회 입장, 모바일 30fps, 그래픽 연결 중단/미완료 입장 자동 경량 복구, 조이스틱·줌·개인 공간·PC 그래픽 회귀 검사를 모두 통과했다. 검수 중 체험판 API 초기화 누락을 발견해 게시 전에 복구했으며, 개인 공간 비동기 입장 대기를 명시한 후 전체 조작 검사를 다시 완료했다. 공개 체험판에 게시한 뒤 동일 엔진의 입장 검사를 재확인한다.

게시 완료: 체험판 v56, 소스 `9aabbf6ebd762869d7eda98e663dc1c605730b09`. 공개 URL에서도 WebKit·Chrome 각각 연속 3회 입장, 입장 전 canvas/엔진 미생성, 30fps 제한 및 온라인 배지를 확인했다. 첫 입장 버튼 이후 측정은 WebKit 6.0초, Chrome 4.3초였으며 Mac에서의 브라우저 모의 수치다. 실제 iPhone의 발열 해소·강제 종료 재발 여부는 사용자의 기기 재확인이 필요하다. 공개 결과는 `published/result.json`, 게시 정보는 `publication.json`이다. 임시 Mac 공유 서버는 유지했다.
