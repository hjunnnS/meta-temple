# 모바일 부하 및 UI·UX 재점검 — 2026-11-21

수정 전 진단 기록이다. 이 문서에서 제안한 모바일·UI 후속 구현과 공개 v61 검수는 [후속 구현 결과](mobile-followup-20261121.md)를 참조한다.

기존 모바일 장애 후속 점검이다. M4 / Epic #4 / Implementation #66 성능 후속 및 #64·#77 사용성 검수와 연결하며 기존 Issue 상태·승인은 변경하지 않았다. 이번 범위는 진단이며 제품 수정·추가 게시·커밋은 수행하지 않았다. 가격·결제는 제외했다.

## 환경과 검수 범위

공개 체험판 https://sasa-temple-personal-trial.fond-bell-1966.chatgpt.site/ 에서 Mac Playwright WebKit·Chrome의 iPhone 14 Pro 모의 환경을 사용했다. UI는 393×852, 320×740, 852×393에서 점검했다. 실제 iPhone의 온도·전력·GPU 시간·iOS 메모리 한계는 측정하지 않았다. 아래 그리기 호출 감소율은 발열 감소율이 아니다. 시험 중 효과를 잠시 끈 비교는 해당 브라우저 메모리에만 적용하고 원상 복구/종료했다.

- 초기 UI 검사 20개 화면에서 가로 넘침·측정된 DOM 본문 14px 미만 글자는 없었다. SVG 지도 번호·숨긴 옵션은 이 글자 집계에서 제외하며 스크린샷으로 별도 확인했다.
- 지도 30회 반복 열기와 이어지는 조이스틱 이동·지도·메뉴 3주기 92.965초 검사: 재로딩·크래시·WebGL 연결 손실 0. 이동은 약 20fps, 열린 지도/메뉴는 각 10초 구간 렌더링 0회.
- 개인 공간 연못→야경→한강→단풍→설경→연못 왕복 완료. 별도 밤바다도 확인했다. 개인 공간 렌더링 중 사찰 프레임 0, 퇴장 후 장면 수 2→1, 재로딩 0.
- WebKit에서는 이전부터 있던 Colyseus WebSocket 생성자 fallback 진단 `Wrong protocol for WebSocket '[object Object]'`가 다시 기록됐다. 연속 검사에서는 이 진단을 명시적으로 분리했고 그 외 pageerror는 없었다. 전체 오류가 전혀 없다고 표현하지 않는다.
- 첫 UI 검사 끝의 실패는 시험 코드가 존재하지 않는 `#private-active-controls`를 기다린 탓이다. 실제 `#private-room-controls`로 수정한 뒤 개인 공간 검사를 따로 완료했다. 제품 실패로 세지 않으며 원시 실패 기록도 보존한다.

## 자원 진단과 우선순위

1. **초기 건물 생성과 상세 데이터 보존**: 측정 시 전체 장면 메시 3,236개·재질 709개, 정리 후 geometry 정점 합 약 159만 중 건물 약 117만이었다. 소스는 모바일에서도 상세 건물을 만든 다음 병합·단순화하고 상세 VertexData를 유지한다. 현재 근접 업로드는 GPU 측면의 절감이며 초기 상세 모델 생성 자체를 모두 없앤 것은 아니다. 모바일은 단순 모델부터 읽고 상세 모델을 실제 근접 시 생성/읽는 구조가 다음 개선 후보다. 전체 정점 합은 실제 GPU 사용 바이트가 아니다.
2. **그림자와 방문객**: 같은 중앙 장면 마지막 기준 표본에서 낮 486.5·밤 496.3 draw calls/프레임. 그림자를 잠시 끄면 404·416으로 약 16~17%, 방문객 표시/갱신을 끄면 426.5·436.3으로 약 12% 감소했다. CPU/GPU와 프레임률·발열 개선 비율로 바꾸어 해석하지 않는다. 방문객은 위치·동작이 변하고 상세 GPU 캐시도 시험 중 퇴거되므로 CPU 시간 비교의 인과 추정에는 한계가 있다. 모델을 삭제하기보다 모바일 그림자 대상/갱신을 거리·시야로 제한하고 먼 방문객의 부품/갱신을 더 합치는 방향을 권장한다.
3. **개인 공간 메모리와 야경**: 사찰은 렌더하지 않지만 메시 3,236개와 약 179만 geometry 정점을 보유한 장면을 그대로 유지한다. 사찰 복귀 정보를 보존하면서 사용하지 않는 상세 버퍼/캐시를 일시 정리할 여지가 있다. 개인 공간 draw calls는 연못 84.5, 야경 210.25, 한강 119.9, 단풍 96.25, 설경 98.25, 밤바다 89.25였다. 같은 카메라 시선이더라도 선택 풍경마다 구성과 효과가 다르므로 야경/연못 약 2.5배는 그리기 호출 비교이며 온도·전력 배수가 아니다. 야경의 창문·차량·글로우 추가 패스 제한을 우선 검토한다.
4. **불필요한 통신 갱신**: 소스상 Colyseus 이동 전송이 100ms 간격이며 같은 자세의 중복 전송이나 document.hidden에 대한 별도 축소가 없다. 공유 상태 조회도 보이는 동안 2초 간격이다. 위치/수행 변화 전송과 저빈도 heartbeat를 구분하고 메뉴/백그라운드에서는 낮추는 후보가 있다. 원격 아바타 보간과 서버 연결 수명을 유지하는 검증이 선행돼야 한다. 이번에 전력 영향량은 계측하지 않았다.

기존 모바일 기본 해상도 제한·20fps·유휴 8fps·명상 15fps·지도/메뉴 렌더 정지는 유지할 가치가 있다. 이번 표본의 공용 렌더 크기는 280×471로 이미 낮아서 해상도를 더 내리는 것보다 그릴 대상·패스·초기 생성을 줄이는 접근이 적절하다. PC 품질은 후속 수정에서도 별도로 유지한다.

## UI·UX 판정

- **유지할 개선**: 의자 터치 앉기와 주문창 요청 시 열기, 공간 메뉴 접기는 과도한 상시 창 문제를 줄였다. 이번 확인의 해당 버튼·메뉴에는 작은 터치 영역이나 가로 넘침이 없었다. 기존 수행 상태·시간·108배 보존 검수는 직전 v60 기록을 참조한다. 이번 점검에서 전체 108배 수행을 다시 실행한 것은 아니다.
- **가로 화면의 시야**: 852×393에서 상단 일정 안내가 약 212×71 CSS px를 차지하고 다른 상단 배지/안내와 함께 보인다. 글자 축소 대신 작은 일정 버튼으로 접거나 가까운 행사일 때만 펼치는 방식을 권장한다. 버튼 가림으로 판정하지 않는다.
- **지도의 이해/스크롤**: 지도 번호는 선명하지만 장소명을 하단 목록과 대조해야 한다. 현재 위치 표시는 있으나 번호만으로 초행 사용자가 전각을 바로 구분하기 어렵다. 목록에 추가 항목이 있다는 시각적 힌트를 주고 선택한 장소를 더 명확하게 강조하는 개선을 권장한다. 첫 자동 검사에서 하단 목록 2개가 가려져 보였지만, 실제 목록을 스크롤한 뒤 천왕문 항목 터치·선택이 정상인 것을 재확인했다. 접근 불가 버그로 세지 않는다.
- **수행 안내의 설명 건너뛰기**: 체크박스는 18×18, 연결된 라벨은 323×24 CSS px다. 라벨을 눌러 토글되지만 높이가 44px보다 작아 모바일 오조작 여지가 있다. 라벨 행 전체 높이를 44px 이상으로 확보하는 것이 좋다. 환경 설정의 3개 체크박스는 라벨 전체가 327×50으로 눌리므로 같은 문제로 분류하지 않는다.
- **커피 주문의 문구**: 버튼은 커피 주문인데 주문창 초기 음료는 차다. 음료 주문으로 통일하거나 처음부터 커피를 선택해 작은 혼동을 줄일 수 있다.

## 자료와 재현

`evidence/mobile-review-20261121/`에 workload, ui-private, private, targets, soak 결과·화면을 보존했다. 기존 `profile-mobile-workload.mjs`, `check-mobile-soak.mjs`와 새 `check-mobile-review.mjs`, `check-mobile-review-targets.mjs`를 사용했다. 성능 측정 브라우저들은 순서대로 실행하고 검사 종료 후 닫았다. 제품 실행 소스는 변경하지 않았다. 실기기 Safari 검증 없이 발열이 해결됐다거나 iPhone에서 같은 fps가 보장된다고 결론 내리지 않는다.
