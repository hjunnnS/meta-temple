# 해태 방향·풍경 경계 및 겨울 숲 수정

사용자 첨부 화면과 수정 요청을 기존 작업의 후속 범위로 반영한다. 새 GitHub 이슈·Milestone·날짜를 만들거나 기존 번호·상태·승인 기록을 변경하지 않는다. 가격·결제와 기존 상품 배치는 변경하지 않는다.

## 기존 작업 대응

- M2 / Epic #1 / Implementation #23 후속: 두 해태를 각 좌대 중심에서 회전시켜 서로 마주 보게 한다. 형상·기존 자리·재질·중앙 통행 간격 유지. 완료: 좌측 얼굴 +X, 우측 얼굴 -X 방향, 기존 골조 회전 보존. 검증: 코 위치의 중심 방향 검사와 천왕문 출구 화면. 예상 S.
- M3 기능 확장 / Epic #1 / 기존 개인 공간 항목 F02 후속: 도시를 방 좌우·뒤편까지 확장하고 도로를 연결한다. 개인 방의 건물 자리와 겹치는 도시 건물은 제외. 강 수면을 x≥26, -35<z<105로 제한해 방의 기초·강변 도로·건물 아래를 덮지 않도록 한다. 강변 도로는 실제 육지로 이동하고 중복 도로 제거. 단풍은 잎 수·밀도를 높임. 설경은 원뿔 대신 침엽수 가지·녹색 잎 뭉치와 그 위 눈, 낙엽수 가지 위 눈을 구성. 사진 배경은 계속 사용하지 않는다. 완료: 첨부와 같은 난간 좌우 끝·아래 시점에서 도시가 이어지고, 수역 밖 구조물이 물 위에 떠 보이지 않으며, 더 풍성한 단풍과 가지 위 눈이 표시됨. 예상 M.
- M4 / Epic #4 / #64·#66 후속: PC·터치 모의 화면, 실제 난간 끝 시점, 전체 풍경 전환·저장·리소스 정리, 렌더 오류 검사. 예상 S. 검수·배포 대기와 외부 준비는 작업량에 중복 가산하지 않는다.

선행: 이번 사용자 수정 승인(충족). 이번 범위는 기존 웹 체험판 보완이며 운영 정책·실기기·공개 운영 호스팅 확정은 포함하지 않는다.

## 검증

- 본 서비스 단위 검사 120건, 체험판 59건 및 양쪽 타입 검사·빌드 통과.
- tests/haetae.test.ts: 양쪽 코의 방향, 위치와 통행 간격.
- tests/scenery-layout.test.ts: 도시의 앞·옆·뒤 지점 점유, 개인 건물 비중첩, 강변 건물 전체의 수역 비침범, 강 표면에서 개인 건물과 양쪽 도로 제외.
- scripts/check-scenery-edges.mjs: PC 1280×850·Chrome 터치 모의 390×844에서 해태, 단풍·설경, 도시·강의 난간 좌우 끝과 아래 화면 확인. 강 수면 제한 활성화, 사진 요청 0건, 실행 오류 없음.
- scripts/check-3d-scenery.mjs: 여섯 풍경 전환·저장과 반복 전환 시 메시·재질 수 정리 회귀 검사.
- 증거: evidence/scenery-edges. 렌더 오류가 없다는 결과는 사용자의 시각 평가나 실휴대폰·50명 부하 합격을 대신하지 않는다.

Mac 임시 접속 통로가 갱신돼 같은 서버의 현재 주소를 함께 반영한다. 공용 기능·시각 품질 및 실제 과금 방식은 변경하지 않는다.
