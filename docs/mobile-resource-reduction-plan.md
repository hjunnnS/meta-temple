# 모바일 부하 감소 후속 방안

2026-11-20. 사용자의 리소스 분석·대책 수립 요청이다. 구현 착수·Issue 생성·배포 승인이 아니다. 기존 M4, Epic #1·#4·#74 및 Implementation #64·#77의 후속 후보로 정리하며 번호·내용·승인 상태는 변경하지 않는다. 날짜는 정하지 않는다. 가격·결제는 제외한다.

## 현재 확인한 사실

공개 v58을 Mac WebKit의 iPhone 14 Pro 화면·터치 조건으로 측정했다. 실제 iPhone 온도·전력·GPU 시간 측정은 아니다. 기본 모바일 가벼움, 280×471 렌더 크기, 동작 중 20fps다. 낮 중앙마당 약 560회, 밤 약 570회의 프레임별 그리기 호출이 발생했다. 방문객 표시·행동을 검사 브라우저 안에서 잠시 제외하면 약 407/417회였다. 이는 방문객 전체 제거 실험이므로 개선 예상치나 온도 감소율이 아니다.

수정된 활성 목록 집계에서 지붕 ridge 계열 6개 묶음의 subMesh 인덱스 합은 2,803,716이었다. 불상의 얼굴·금동 몸체·머리 장식 계열도 상위에 있었다. getTotalIndices는 공유 인덱스 버퍼 전체 크기를 반환하는 경우가 있어 이 세부 순위에는 실제 subMesh 범위를 합산했다. 이 합계도 GPU 시간이나 모든 렌더 패스의 삼각형 처리량을 뜻하지 않는다. 원시 결과는 `evidence/mobile-resource-plan/breakdown.json`이다.

건축 병합은 재질을 먼저 묶고 10만 정점이 넘는 재질만 모바일 공간 분할한다. 그 이하의 같은 재질 부품은 서로 다른 건물에 있어도 한 묶음이 될 수 있다. 나무는 이미 28m/70m 기준의 3단계 표현을 사용한다. 따라서 나무를 일괄 삭제하는 것을 우선 대책으로 잡지 않는다.

지도 열림 중 렌더링 0fps, 무입력 45초 뒤 15fps, 명상 중 20fps는 동작했다. 자동 절전은 프레임 지연을 감지하며 온도·전력에는 반응하지 않는다. 그림자 512px/6프레임, 연못 반사 512px/12프레임, 번짐용 화면 512px·512px·256px가 있었다. 네트워크 이동 송신은 100ms 간격이며 이번 측정에서 그래픽보다 주원인이라고 판단할 근거는 없다.

## Milestone 및 Epic의 완료 방향

기존 M4의 모바일 안정화 후속으로 PC 결과를 유지하고 모바일의 실제 그리기 작업·초기 생성 최고 부하를 낮춘다. 기존 Epic 연결은 유지하고 실행 항목을 #77의 장면 부하, #64의 초기 입장 안정성 후속으로 검토한다. 온도 해결이라는 완료 조건은 에뮬레이터만으로 충족했다고 표시하지 않는다.

## 우선순위와 실행 후보

1. **건물·불상·지붕을 거리와 공간에 맞게 준비 (#77, 예상 M).** 가까운 지붕 윤곽·단청·불상을 유지하고 먼 기와 골·끝 장식은 단순 모델이나 표면 표현으로 대체한다. 전각별 내부 그룹을 분리해 실제 보이는 출입구·실내만 처리한다. 먼저 대표 전각 한 곳의 전후 호출 수와 CPU 구간을 비교한 뒤 확장한다. 선행 관계 없음. 완료 조건은 근거리 외형·전각 진입·불상 안내 유지, 카메라 회전 시 갑작스러운 소실 없음, 동일 장면 부하 감소다. 지나친 소규모 병합 분할은 앞선 실험에서 호출 수를 늘렸으므로 결과를 측정하며 적용한다.
2. **방문객 표시 부품 통합 (#77, 예상 M).** 사람 수·행동·근거리 외형을 유지하고 중거리·원거리 캐릭터의 여러 작은 부품을 소수의 묶음으로 만든다. 공통 geometry 공유만으로는 재질·메시별 호출이 사라지지 않는다. 1번의 대표 전각 검증 후 진행한다. 완료 조건은 동일 인원에서 호출 감소, 접근 시 외형 복구, 걷기·참배·명상·12지신·법복·실제 사용자 구별 유지다.
3. **모바일 정지 화면의 지속 처리 감소 (#77, 예상 S~M).** 무입력 15fps에서 추가 절전 단계와 정적 장면 재사용을 검토한다. NPC와 수행의 시간 진행은 유지하며 실제 조작·수행 시작에는 즉시 복귀한다. 명상은 캐릭터 자세·소리·시간 표시가 유지되는 별도 낮은 갱신 예산을 검증한다. 2번 이후 진행한다. 완료 조건은 장기 정지 상태의 프레임 수 감소, 첫 터치 손실 없음, 수행 시간·자동 108배 횟수 정확성이다.
4. **그림자·반사·번짐의 화면별 예산 (#77, 예상 S~M).** 가까운 주요 그림자는 유지하고 원거리 장식의 그림자를 제외한다. 카메라·대상이 움직이지 않을 때 재계산 간격을 늘리고, 반사가 보이지 않는 방향에서는 반사 화면 생성을 중단하는 방안을 시험한다. 낮/밤의 연등·건물 안내 가시성을 유지한다. 3번 이후 진행한다. 완료 조건은 보이지 않는 효과의 반복 갱신 감소, 밤길 시인성·반사 복귀 정상, 개인방 풍경 전환 자원 누적 없음이다.
5. **입장 시 최고 생성 부하 분산 (#64, 예상 M~L).** 현재는 모든 정적 건축을 먼저 만들며 잠깐씩 입력 처리에 양보한다. 가까운 입장 공간과 저밀도 원경부터 준비하고 먼 세부 자산은 이동 필요에 따라 준비·해제하는 방향을 검토한다. 1번의 구역별 모델 구성이 선행이며 구현 난도가 높아 마지막에 둔다. 완료 조건은 입장 구간의 가장 긴 작업과 최고 메모리 감소, 언어·시작 버튼 반응 유지, 지도 이동·공유 방문객·개인방 복귀 중 누락 없음이다.

각 항목의 예상량은 구현만의 정성 추정이며 합산 일정이 아니다. 브라우저 검증 시간과 실기기 확보·검증 대기는 별도로 둔다. 구체적인 실행 Issue 분할과 상태 변경은 구현 승인 후 기존 항목을 확인하고 결정한다.

## 검증 방식

동일 공개 소스·기본 모바일 설정·1명 실제 사용자/19명 가상 방문객·동일 카메라를 고정해 입장, 중앙마당 낮/밤, 전각 안, 연등 주변, 개인방을 비교한다. 호출 수, 실제 subMesh 범위, main-thread 장면 처리 시간, 초기 최고 JS 메모리와 긴 작업, 정지 상태 프레임 수를 구분해 기록한다. 이번에는 GPU 시간·전력·실제 온도를 기록하지 않았다.

각 변경은 개선 대상 장면에서 부하가 줄고 PC 외형 비교와 조작 검사가 통과해야 다음 단계로 간다. 마지막에 일반 애니메이션 10분 반복, 지도·메뉴·회전·수행·3개 브라우저 동시 접속을 검증한다. iPhone 14 Pro Safari의 발열·강제 재로딩 해결 판정은 별도의 실제 기기 검증 항목으로 남긴다. 에뮬레이션 통과나 fps 유지만으로 온도 해결을 선언하지 않는다.
