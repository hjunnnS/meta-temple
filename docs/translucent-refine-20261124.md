# 반투명 메뉴 투명도 보정

사용자 첨부의 메인 메뉴·체험판 안내창이 여전히 불투명하게 보인다는 피드백에 따른 보정이다. 기존 M4 / Epic #1·#74 / Implementation #64·#77의 후속으로 기록하며 별도 Issue나 목표 날짜는 만들지 않는다. 예상 작업량 XS, 화면 검수·게시 대기는 별도다.

## 변경과 완료 조건

- 일반 팝업의 배경 불투명도 94% → 68%, 하단 메뉴 80% → 65%. 어두운 녹색을 조금 더 깊게 해 밝은 배경에서도 글자를 읽을 수 있게 한다.
- 일반 버튼은 불투명한 면 대신 16% 불투명도 배경으로 바꿔 팝업과 함께 배경이 보이게 한다. 선택·주요 실행의 금색 강조는 유지한다.
- 체험판 안내창·일정 표시도 같은 녹색 반투명 배경과 밝은 글자로 통일한다. 지도·설정 등 정보량이 많은 읽기/입력 표면은 밝게 유지하고 불투명도만 98.5% → 94%로 줄인다.
- 뒤쪽 화면을 어둡게 덮는 모달 배경도 30% → 18%로 줄인다. 글자·아이콘 자체의 투명도와 메뉴 크기는 바꾸지 않는다.
- 실시간 블러와 추가 3D 렌더는 사용하지 않는다. PC 그래픽·기능·가격·결제·통신은 변경하지 않는다.

검수 중 기존 Mac 임시 터널이 자동 재시작하며 주소가 바뀐 것을 확인하여 연결 상수만 현재 주소로 갱신했다. 서버 프로토콜·인원 조절은 변경하지 않는다.

## 검증

PC Chrome과 모바일 WebKit에서 낮·밤, 320px 세로·852px 가로, 팝업·버튼의 실제 투명도, 글자 대비, 블러 미사용, 메뉴 중 렌더 중지, 주문·개인 공간 복귀를 확인한다. 체험판 안내와 환영창·일정도 추가 확인한다. 실기기 발열 측정은 포함하지 않는다.

원시 결과는 `evidence/translucent-ui-20261124-refine/`에 기존 검수와 구분해 보존한다.

대비 계산은 팝업 뒤의 3D 화면이 흰색인 경우를 가정하고 팝업 내부 배경만 합성하도록 보완했다. 캔버스 아래의 어두운 body 색을 사용하지 않는다.

## 로컬 결과

- PC 1440×900 및 WebKit 모바일 393×852, 추가 320×740·852×393 화면 검수 통과. 낮·밤, 일반 버튼/호버/선택/비활성화 상태를 확인했다.
- 대상 어두운 팝업의 최소 텍스트 대비 5.27 이상, 하단 메뉴 5.52 이상. 지도 등 밝은 정보 창은 기존 글자/배치와 함께 별도 유지했다.
- 일반 팝업 alpha .68, 하단 .65, 일반 메뉴 버튼 .16, 밝은 정보 창 .94 계산 스타일 확인. 모바일 메뉴 중 렌더 중지와 PC·모바일 backdrop-filter none 확인.
- 주문 열기·닫기, 개인 공간 메뉴·사찰 복귀 통과. 두 소스의 TypeScript 및 배포 빌드 통과.
- 초기 진단 local/의 임시 주소 오류와 verified/의 흰색 배경 호버 대비 부족은 보정 후 final/에서 재검수해 통과했다. 원시 실패 기록도 남긴다.

## 게시 결과

체험판 v63 게시 성공. 공개 주소에서도 PC·WebKit 모바일의 같은 검수를 재실행해 통과했다. Mac 공유 서버 정적 파일 181개도 동일 빌드와 일치한다. 상세 응답과 검수 화면은 publication.json 및 published/에 보존한다.
