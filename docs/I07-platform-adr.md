# ADR-001 / I07 #10 — 웹·앱 렌더링 관계

상태: **제안**. 실제 모바일 기기 미정이며 최종 승인 전이다.

## 제안

웹을 먼저 출시하고, 앱은 동일 TypeScript·Babylon.js 렌더러/에셋/상태 표시 코드를 WebView 런타임(Capacitor 후보)에서 재사용한다. 별도 네이티브 3D 렌더러는 이번 범위에 포함하지 않는다. 앱 출시 시점·국가·지원 OS는 P10 승인 필요. 이 제안은 앱 기능 취소나 자동 승인된 출시 순서가 아니다.

공유: 공간·좌표 계약, 모델·재질, 3D 선택·표시, UI 상태, 서버 API 클라이언트.
플랫폼별: 인증 외부 브라우저/딥링크·중단/복귀·안전한 저장소·스토어별 결제/환불 브리지·수명주기·권한. 계정·주문·설치 원본은 서버 공통.
앱을 다시 열 때 로컬 캐시만으로 결제 성공을 판정하지 않으며 원거래와 권리를 재조회한다.

## 대안과 비용 영향

1. 웹 3D 재사용: 에셋·렌더러 유지 지점 하나. WebView 메모리·OS 그래픽 차이를 실제 기기에서 확인해야 한다. 단일 코드가 동일 성능을 보장하지 않는다.
2. 별도 네이티브 렌더러: 플랫폼 최적화 여지가 있지만 모델/재질 변환·셰이더·상태 표시·카메라·입력·검수의 중복 범위 증가. 현재 별도 구현/실측/비용 견적 없음.
3. 앱 후속 출시: 웹 실측과 거래 검증 후 앱 범위를 확정. 앱 전용 과제는 추가 승인 전 구현하지 않는다.

결정 증거: I01 같은 장면의 최저 모바일 브라우저 및 후보 앱 빌드 측정, 렌더 크기·FPS·메모리·로딩·발열·중단/복귀 기록. 현재 앱 빌드 실측 없음. 검증 없이 재사용/별도 렌더러의 우열을 주장하지 않는다.

결제: 판매 국가·배포 채널·디지털 상품 성격을 기준으로 당시 공식 스토어 규정과 제공자 조건을 확인한 뒤 P10에서 선택한다. 현재 웹 결제/앱 내 결제를 단정하거나 외부 결제 링크를 구현하지 않는다.
계정 제안: 익명 탐방 허용, 예약·결제 전 로그인, 서버 소유권 복원. P01 로그인 제공자·복구 정책은 미확정.

근거: [Capacitor 공식 소개](https://capacitorjs.com/docs) — 웹 기술을 네이티브 컨테이너에서 재사용하고 네이티브 SDK 기능을 연결하는 런타임. 확인일 2026-11-06. 이번 문서는 성능 보증이 아니다.
