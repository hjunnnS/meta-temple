# 반투명 메뉴 적용

2026-11-24 사용자 승인. 기존 M4 / Epic #1·#74 / Implementation #64·#77 사용성 후속으로 진행한다. 기존 Issue 번호·승인 상태·Milestone은 보존하며 새 Issue·목표 날짜를 만들지 않는다. 예상 구현 S, 화면 검수 및 게시 대기는 별도다.

## 범위와 완료 조건

- 하단 메뉴와 작은 조작 버튼은 짙은 녹색 반투명 배경, 따뜻한 흰색 글자, 얇은 테두리로 바꾼다.
- 일반 메뉴·수행 선택·내 모습·가이드·일정·커피 주문·개인 공간 메뉴는 더 진한 반투명 녹색으로 표시한다. 주요 선택/실행은 밝은 금색과 진한 글자로 구분한다.
- 지도·설정·계정·개인 공간의 정보/입력 창은 거의 불투명한 밝은 읽기 표면을 유지한다. 접수·가격·결제 로직은 변경하지 않는다.
- 배경 전체를 흐리는 실시간 backdrop blur는 사용하지 않는다. 글자나 자식 컨트롤 전체의 opacity를 낮추지 않고 배경색의 alpha만 조정한다.
- 기존 메뉴 크기·스크롤·뒤로·닫기·터치 영역·수행 동작과 PC의 3D 그래픽은 유지한다.

수정은 `src/translucent-ui.css`, 해당 CSS를 가져오는 main 진입부와 기존 하단 메뉴의 블러 제거다. 장면·모델·조명·프레임 예산은 바꾸지 않는다. 검수에서 기존 Mac 공유 서버가 종료되어 있음을 발견하여 기존 supervisor를 재실행하고 임시 주소 상수만 갱신했다. 통신 프로토콜은 그대로다. 반투명 색상 합성 자체의 비용이 0이라는 주장이나 실기기 발열 해결 주장은 하지 않는다.

## 검증

PC 및 WebKit 모바일 모의 환경의 낮·밤 메뉴, 좁은 화면과 가로 화면, 글자 대비·선택 상태·메뉴 닫기·주문·개인 공간 복귀를 확인한다. 밝은 배경을 가정한 합성 색상에서 일반 글자 4.5 이상, 큰 글자 3 이상을 기준으로 확인하며 대비가 낮으면 배경과 글자 색을 보완한다. 모바일 메뉴 중 3D 렌더 중지와 블러 미사용도 확인한다. 실제 휴대폰 온도 측정은 포함하지 않는다.

원시 결과와 화면은 `evidence/translucent-ui-20261124/`, 검사 코드는 `scripts/check-translucent-ui.mjs`에 보존한다. 결과와 게시 정보는 완료 후 추가한다.

## 로컬 검수 결과

- PC Chrome 1440×900, WebKit 모바일 393×852, 추가 320×740·852×393 화면의 낮·밤 메뉴 검수 통과. 대상 어두운 메뉴의 글자 대비는 일반 글자 4.5 / 큰 글자 3 기준을 통과했다. 지도·설정은 별도 밝은 표면을 유지했다.
