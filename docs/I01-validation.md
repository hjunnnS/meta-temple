# I01 #5 — 실제 엔진 검증

## 2026-11-06 사용자 확정 변경 — 이전 조건보다 우선

- 개발·검수 기준은 웹이다. 앱은 후속 검토이며 필요 시 하이브리드 포장을 검토한다. 앱 구현·실측·스토어 결정은 현재 M1 선행 조건이 아니다.
- 현재는 그래픽 품질을 우선한다. 저사양 모바일 최적화·실기기 통과는 후속 검증으로 이연하며 현재 M1을 차단하지 않는다. 웹에서 측정 가능한 성능 기록은 계속 보존한다.
- 사찰 배치는 기존 기획서 구조를 따른다. 배치된 모든 건축 구조물은 출입할 수 있어야 하며 실내가 있는 건물에는 탐방 가능한 내부를 포함한다. 문·누각은 통과/진입 가능한 구조로 구현한다. 석탑 등 내부 공간이 없는 조형물의 인위적 실내를 뜻하지 않는다.
- 전체 배치·실내 제작은 기존 M2 공간 제작 Issue에서 수행한다. M1 샘플을 전체 맵 완성으로 간주하지 않는다. 실행 데이터의 임시 치수·좌표가 원본 기획서를 대체하지 않는다.
- 시각 품질은 사용자가 실제 화면을 본 후 판단한다. 기존 캡처는 검증용 초안이며 승인된 최종 품질이 아니다.


현재 검수 대상은 웹 구현과 시각 품질이다. [검수본·같은 버전의 화면·측정 기록](I10-status.md)에서 확인한다.

## 구현된 증거

`src/scene.ts`: 실제 WebGL 장면, 곡면 처마·기와 능선·기단·계단·기둥·창살·직접 그린 단청 패턴, 연등 캐노피, 낮/해질녘/밤. 정식 건축 고증 완료 모델이 아닌 M1 형상 샘플이다.
정적 형상은 재질별 병합, 반복 연등은 thin instances. 소유 샘플 3개만 개별 메시로 강조한다. 문자열 슬롯 ID와 좌표는 품질/선택/샘플 수에 독립적이다. 캡·줄·발광 표현을 포함한다.

`src/main.ts`, `src/metrics.ts`: 측정 시작/종료/JSON 저장. 설정·카메라·렌더 크기·샘플 수·평균 FPS·최악 1% FPS·최장 프레임·실제 렌더러·첫 준비 프레임 시점 기록. 측정 도중 설정 변경, 화면 크기 변경, 탭 숨김은 무효. 정지 후 설정을 바꿔도 과거 기록을 현 설정의 증거로 사용하지 못한다.
JS heap은 브라우저가 제공할 때만 기록하며 GPU/전체 프로세스 메모리로 해석하지 않는다. 기기 모델 직접 입력도 `physicalDeviceVerified`를 자동 승인하지 않는다.

## 엔진 후보 비교

- Babylon.js: 카메라·그림자·glow·인스턴싱을 활용해 검증 장면을 실제 구현. 이번 프로토타입 후보.
- Three.js: 렌더링 중심 구성의 대안. 이번에는 동일 장면을 제작·실측하지 않았으므로 속도·품질 우열을 주장하지 않는다.
- Unity: 별도 에셋/배포 흐름 검토 대상. 현재 동일 빌드 실측 없음.

후보 비교는 기능 적합성 검토이며, Babylon.js 최종 승인 근거는 동일 장면의 승인 기기 실측과 화질 판정이어야 한다. 엔진 최종 확정은 보류.
공식 근거: [Babylon 기능](https://www.babylonjs.com/specifications/), [thin instances의 가시성 단위와 한계](https://doc.babylonjs.com/features/featuresDeepDive/mesh/copies/thinInstances), [그림자](https://doc.babylonjs.com/features/featuresDeepDive/lights/shadows). 확인일 2026-11-06.

## 재현

1. `npm ci && npm run build`, `npm run preview`로 production 빌드 실행.
2. 기기·OS·브라우저·빌드 SHA·네트워크·뷰포트를 기록. 로컬 dev 서버 측정은 최종 배포 로딩 증거가 아니다.
3. 낮/해질녘/밤, 품질 high/low, 연등 100/300/500/1000 중 해당 조합 선택. 비교 중 해상도·밀도를 몰래 낮추지 않는다.
4. 전체·정면·단청·내 연등 구도를 캡처. 3개 내 연등을 번갈아 선택해 나머지 기본 강조 유지 확인.
5. 측정 시작→예열→승인 동선/시간→종료→JSON 저장. 현재 2초 예열은 짧은 기능 확인용이며 Q05의 2분 예열·5분 동선 3회·20분 지속 실행을 대신하지 않는다.
6. 첫 방문 로딩은 캐시 없는 새 방문, 재방문은 같은 버전의 캐시 사용 방문으로 구분한다. 현재 JSON만으로 캐시/네트워크 조건이 검증되었다고 주장하지 않는다.
7. 웹 장면과 동일 설정의 실측을 시각 판정에 연결한다. 저사양 모바일 검증은 후속 기기 선정 후 진행한다.

## 한계

- 공개 서버, 실물 저사양 휴대폰, 네이티브 앱 빌드, WebGPU는 미검증.
- 미니맵·보행 충돌·1인칭·종교 의례·서버 소유권은 이번 장면에 없음. M2/M3 구현을 선행 완료로 주장하지 않는다.
- 샘플 밀도는 생성 수다. 카메라 밖 연등 수와 실제 화면에 보이는 수는 다를 수 있다.
- 합격된 시각 기준선이 아직 없으므로 프로토타입 캡처를 승인 이미지로 표시하지 않는다.
