# 모바일 최적화·UI 후속 구현

사용자가 2026-11-21 승인한 모바일 후속 수정이다. M4 / Epic #4의 Implementation #66 성능 후속, Epic #3의 #68 동기화, #64·#77 사용성 후속과 연결한다. 기존 번호·내용·승인 상태와 실제 Milestone을 바꾸거나 중복 Issue를 만들지 않는다. 새 목표 날짜는 정하지 않는다.

선행 순서: 초기 생성 최적화 → 그림자·방문객 → 개인 공간 캐시·야경 → UI → 로컬 회귀 검사 → 기존 공개 체험판 게시. 예상 구현량 L, 검증 M이며 외부 대기는 별도로 둔다. 완료 조건은 단위 검사·빌드, WebKit/Chrome 터치·가로·320px·기존 수행 흐름, PC 모델·재질 비교, 공유 접속 회귀 및 게시 후 확인이다. 가격·결제·PC 그래픽 변경, 정식 종교/원어민 검토와 5명 평가는 제외한다. 실제 iPhone 온도는 측정하지 않는다.

## 변경

- 모바일 지붕 장식과 불상 머리·옷 상세 모델은 근접 시 원본 생성식으로 준비한다. PC는 같은 생성식·좌표·재질을 유지한다.
- 모바일 근거리 그림자, 원거리 6부품 방문객, 공용 프록시 재질과 원본 버퍼 복사 보호를 적용한다.
- 개인 공간 입장 시 사찰의 상세 GPU 캐시를 비우고 복귀 시 근접 모델을 복원한다. 모바일 야경의 전체 장면 글로우 패스는 발광 창문 재질로 대체하고 차량 18개는 1회 묶음으로 그린다. PC 야경 효과는 유지한다.
- 중복된 자세·스냅샷을 줄이고 비활성 페이지에서 공유 연결을 정리한다. 이동·참배는 100ms 전송 간격과 복귀 재접속을 유지한다. 개인 공간 공용 조회는 중단하고 지도/메뉴 조회는 낮추며 복귀/닫기 시 갱신한다.
- 가로 모바일 일정 접기, 지도 선택·목록 스크롤 힌트, 44px 설명 건너뛰기, 커피 기본 선택을 반영한다. 번역 사전의 기존 문구는 보존한다.

## 검증

- 단위 검사 원본 141개·체험판 80개 통과. 두 빌드와 소스 동기화 확인.
- WebKit·Chrome 모바일: 가까운 원본 모델 ↔ 먼 6부품 모델 복귀, 상세 지붕 생성과 전체 인덱스 범위, 유효 geometry, 44px 설명 건너뛰기, 지도 19번 선택·목록 접근, 90.3×44px 가로 일정 버튼, 커피 기본 선택, 개인 공간 3회 왕복 통과. 연속 왕복 후 public scene 메시 수는 3,127개로 동일했다. 개인 공간에서 public fine 모델 0, 퇴장 후 scene 1개를 확인했다.
- 기존 의자·주문·개인 공간 메뉴·명상 타이머·자동 108배 1회 카운터·복귀 흐름은 WebKit·Chrome·PC에서 통과했다. 전체 108회 실시간 완주를 뜻하지 않는다.
- PC 건물·지형의 geometry와 재질 속성·해상도, 캐릭터 geometry·색·부착물 비교를 통과했다. 기본 GPU Canvas 비교에서는 화강암 텍스처 두 참조의 해시 차이가 있어 진단 원문을 보존했다. 두 버전을 같은 CPU Canvas 그리기 조건으로 제어한 검사에서는 생성 픽셀까지 일치했다. 재질 생성식은 바꾸지 않았다. 캔버스 래스터화 조건 차이로 보이며 기본 GPU 경로의 모든 실행이 픽셀 단위로 같다는 주장은 하지 않는다.
- 세 독립 브라우저의 실제 Colyseus 연결: 상호 이동·12지신 얼굴·법복·참배·개인 공간 격리·복귀·오프라인/재접속 통과. 키 반복 입력을 포함한 통신 검사에서 6.1초 정지 중 move 4회, 1.2초 이동 중 12회, 시험용 visibility 이벤트로 숨긴 1.5초 동안 0회를 확인하고 재가입했다. visibility 검사는 합성 이벤트이며 실제 iPhone의 앱 전환 검사를 뜻하지 않는다.

### 같은 조건의 자원 비교

Mac의 iPhone 14 Pro 모의 환경에서 기존 공개 v60과 수정본을 비교했다. 실기기 온도·전력·GPU 메모리는 측정하지 않았다. WebKit 그리기 비교는 presence를 격리해 가상 방문객 20명을 고정하고 같은 카메라·낮/밤·280×471 렌더 크기·20fps에서 안정화 후 각각 두 번의 3초 표본 평균을 냈다.

- 낮 draw calls 486.5→388.8(약 20.1% 감소), 밤 495.8→401.3(약 19.1% 감소).
- JavaScript heap은 별도 Chrome에서 강제 GC 후 294,238,476→246,065,648바이트(약 16.4% 감소), 같은 초기 시점의 geometry 정점 합은 1,684,369→1,464,671(약 13.0% 감소). 실제 GPU 바이트나 모든 위치의 최대 메모리가 아니다.
- 초기 long task 최대값 204→220ms. 줄었다고 결론 내리지 않으며 전체 로딩 시간/초 단축도 입증한 것으로 표현하지 않는다. 공개 URL과 localhost의 네트워크 조건이 달라 단순 입장 시간 비교는 개선 근거로 쓰지 않는다.
- 개인 공간 야경 draw calls는 직전 감사 표본 210.25→112.25 수준(약 46.6% 감소). 연못·한강·단풍·설경 왕복 완료, 개인 공간에서 공용 사찰 렌더 프레임은 0이었다. 카메라·순서별 표본이며 모든 시선의 비용이나 발열 감소율은 아니다.

중간 실험과 최종 자료는 구별한다. 첫 통신 검사의 숨겨진 내부 상태 요소를 visible로 기다린 실패는 attached로 수정했다. 메모리 중간값에서는 원거리 모델 중복과 상세 배치 범위를 보정했고, 자료형 오류로 빌드가 갱신되지 않은 표본은 `memory-stale-build-diagnostic`으로 분리했다. 이 값들을 최종 절감 수치로 사용하지 않는다.

실기기 온도 측정은 포함하지 않는다. WebKit의 기존 WebSocket 생성자 fallback 진단은 SDK 진단으로 분리했고 기타 pageerror와 geometry 실패는 없었다. 원시 자료는 `evidence/mobile-followup-20261121/`에 있다.

### 연속 사용 검사

WebKit·Chrome 각각 지도 40회 반복 후 조이스틱 이동·지도·메뉴 10주기를 정상 애니메이션으로 검사했다. presence를 격리해 브라우저 간 참가/퇴장으로 메모리 값이 변하지 않게 했다. 각 이동/지도/메뉴 구간은 10초다. WebKit 309.913초·Chrome 310.334초 동안 재로딩·크래시·그래픽 연결 손실 0, 이동은 약 20fps, 지도·메뉴는 렌더 프레임 0을 유지했다. Chrome의 강제 GC 후 JS heap은 시작 245,821,600→종료 247,752,124바이트로 약 0.8% 증가했다. 모든 시간 범위의 누수 부재나 실기기 발열 해결을 입증하지 않는다.

프랑스어·독일어·러시아어의 320px 지도와 852×393 일정·44px 안내 체크를 확인했다. 일정이 없는 이동 완료 위치에서 창을 찾은 첫 시험은 천왕문 보기로 위치를 고정해 바로잡았다. 별도 화면 검토에서 선택된 지도 버튼의 밝은 배경에 흰 글자가 겹친 것을 발견해 진한 글자로 수정하고, 360px 이하에서는 분류 버튼을 두 열로 정리했다. 최종 언어 검사에는 선택 버튼 명암비 4.5 이상 검사를 추가한다.

## 게시

기존 공개 체험판 61버전 게시 성공. 소스 커밋은 `eb05f50877e966db3108497c0c132e8a4b54b4eb`이며 기존 공개 범위를 유지했다. 주소는 https://sasa-temple-personal-trial.fond-bell-1966.chatgpt.site/ 이다. Mac 공유 서버의 정적 화면도 검수한 181개 파일의 SHA-256이 일치하는 빌드로 맞췄다. 공유 서버 프로세스나 가격·결제 설정은 변경하지 않았다. 게시 영수증은 `evidence/mobile-followup-20261121/publication.json`에 보존한다.

공개 URL에서 WebKit 모바일 모의 환경의 의자 터치·드래그 구분, 주문창 요청 시 열기·착석 유지, 접힌 개인 메뉴, 명상 시간, 자동 108배 `1 / 108`, 사찰 복귀 검사를 통과했다. Chrome 모바일 모의 환경에서는 새 상세 모델 생성·인덱스 범위·가까운 캐릭터 복원·그림자·지도 선택·44px 체크·가로 일정·커피 기본 선택과 개인 공간 3회 왕복을 다시 통과했다. 결과는 `published-rest/`와 `published-integration/`에 있다. 게시 후 geometry 오류와 추가 pageerror는 없었고 WebKit의 알려진 SDK fallback 진단은 별도 기록했다.
