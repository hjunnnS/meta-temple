# 사사 전체 UI 설계 v1

2026-11-10 작성. 현재 구현과 승인된 방문·구매·수행 흐름을 기준으로 한 화면 구조 초안이다. ui-v1.html에서 17개 화면과 웹·모바일 웹 구성을 눌러 볼 수 있다. 결제·로그인은 화면 흐름 시연이다.

## 화면의 공통 구성

- 산 배경과 연꽃, 기억한 언어로 입장한다. 입장 후 기본은 3인칭이다.
- 탐방 화면 상단에 사찰 이름·메뉴·계정, 작은 현재·다음 일정 표시를 둔다. 하단에는 현재 장소와 현장 행동을 둔다.
- 웹에서는 오른쪽 패널, 모바일 웹에서는 하단 패널을 사용한다. 한 번에 하나만 열고 닫으면 원래 카메라와 선택 상태로 돌아온다.
- 주조색은 짙은 녹색, 패널은 따뜻한 회백색, 강조는 절제된 금색을 제안한다.
- 검수용 시점 목록·샘플 소유 제어·진단 기록은 개발용 화면에서 제공한다. 방문자 공간 메뉴는 실제 장소 이름을 ㄱㄴㄷ 순으로 표시한다.

## 전체 화면과 흐름

1. 입장. 산 배경·연꽃·14개 언어·기억한 언어·준비 중·재시도.
2. 탐방. 이동·확대·다른 방문자·현재 위치·현장 행동.
3. 전체 메뉴. 공간·일정·수행·접수·내역·설정.
4. 하루 일정. 한국 시간의 네 일정·현재와 다음 대목·듣기와 중지.
5. 아이템. 연등·소원패·인등·추모등·봉헌초의 의미와 기간·가격.
6. 자리 선택. 연등은 위에서 줄 선택 후 확대, 다른 아이템은 실제 구역에 맞춘 자리 선택.
7. 선택한 자리. 고유 번호·위치·기간·가격·신청 정보 준비.
8. 신청 정보. 표시 이름·문구·이름표·공개 동의·입력 오류.
9. 로그인. 이메일 링크·Google·Apple·취소·만료·실패와 원래 작업 복귀.
10. 예약·결제. 확보한 자리·남은 시간·주문·취소·가격 변경 재확인.
11. 설치·복구. 진행·완료·재시도·환불·만료와 같은 주문 상태 확인.
12. 수행. 참배·108배·현재 횟수·중지·재시도·완료.
13. 소원 동전. U자 물가 접근·3/2/1·투척·성공 효과·실패 파문.
14. 내 내역. 현재 설치·처리 중·만료·환불·계정 관리.
15. 공개 상세. 공개 문구·공유·신고·숨김·만료·공개 중단.
16. 설정. 품질·효과 완화·소리·언어·계정.
17. 운영. 접수·환불, 상품·자리, 문구 감수, 개인정보 처리와 장애 알림.

## 승인된 동작을 지킬 부분

비회원은 탐방·관람·자리 선택·신청 정보 준비를 이용한다. “이 자리에 예약”에서 로그인하고 같은 상품·자리·기간·입력으로 복귀한다. 108배에서 로그인하면 원래 법당으로 돌아온다.

결제 결과 확인 중 새 주문을 만들지 않는다. 설치·복구·환불은 같은 주문의 상태로 표시한다. 설치된 아이템의 위치와 소유자 강조를 유지한다. 내 아이템 찾기·자동 이동은 추가하지 않는다.

공개 동의 기본값은 비공개다. 소원패·연등 이름표는 기존 신청 설정을 따른다. 가격·기간·환불은 승인된 시험 기준을 사용하며 출시 정책은 별도 결정한다.

## 정상·오류·접근성

빈자리·예약 중·사용 중·만석·연결 실패를 구분한다. 입력 오류는 해당 필드에 연결하고 입력을 보존한다. 로그인·결제·설치 진행 중 중복 실행을 막는다. 연결 복귀 시 최신 자리와 주문 상태를 확인한다.

키보드로 메뉴와 패널을 열고 닫고 초점을 실행 버튼으로 복귀한다. 터치 영역은 최소 44px로 한다. 상태는 색과 글자를 함께 쓴다. 효과 완화는 수행·동전·법복 전환에 일관되게 적용한다. 모바일 웹과 14개 언어의 긴 문구를 함께 검수한다.

## Milestone·Epic·Implementation Issue 적용 순서 제안

기존 이슈의 UI 보완 범위이며, 신규 이슈를 등록하지 않았다. 기존 번호와 승인 상태는 보존한다. 실제 서비스 UI 적용은 시안 검토 후 진행한다. 목표 날짜는 설정하지 않는다. 예상량은 구현만 합산하며 검토·정책·외부 설정 대기는 별도다.

### M2 · 공통 화면 틀

Epic #1 사찰 공간과 방문 경험, Epic #4 계정·플랫폼·운영·출시.
Implementation #27에서 탐방 메뉴·설정·웹 패널·모바일 하단 패널과 접근성을 정리한다.
선행은 기본 화면의 시각 검토다. 완료 조건은 메뉴·설정·닫기·초점 복귀를 웹과 모바일 웹에서 이용하는 것이다.
검증은 320px·390px·데스크톱, 키보드와 효과 완화다. 예상 1~2인일.

### M3 · 방문·수행

Epic #1과 Epic #3 실시간 방문과 상태 동기화.
Implementation #35·#53에서 첫 방문 안내·방문자·참배 상태를 새 화면 틀에 연결한다. 일정·108배·동전은 현재 구현의 화면을 정리한다.
선행은 #27의 공통 틀이다. 완료 조건은 입장·탐방·현장 행동과 108배 로그인 복귀가 이어지는 것이다.
검증은 비회원·재방문·중간 예불 입장·수행 중지·통신 복귀다. 예상 1~2인일.

### M3 · 신청·계정

Epic #2 상품·슬롯·구매·내 상품, Epic #4.
Implementation #37·#38·#39·#41·#44·#45·#48·#51의 자리·문구·예약·설치·내역·공개 상세 화면을 연결한다.
선행은 공통 틀과 자리 선택 화면 검토다. 완료 조건은 다섯 상품 모두 예약 시 로그인하고 같은 선택으로 복귀해 주문 상태를 확인하는 것이다.
검증은 만석·동시 선택·로그인 취소·만료·가격 변경·결제 응답 유실·복구·환불과 다국어다. 예상 3~5인일.

### M3 · 운영

Epic #4.
Implementation #55~#60의 권한·상품·주문·문구·개인정보·장애 화면을 업무별로 정리한다.
선행은 운영 화면 검토다. 완료 조건은 권한별 동작과 대상·사유·결과·감사 기록의 연결이다.
검증은 역할별 접근·최신 상태 재확인·실패와 재시도·사유 누락 방지다. 예상 1~2인일.

### M4 · UI 통합 검수

Epic #4.
Implementation #64·#65·#71에서 최신 UI의 방문·구매·재방문·접근성·거래 상태와 인계 기록을 검증한다.
선행은 위 UI 보완 완료다. 완료 조건은 주요 정상·오류 흐름과 모바일 웹·14개 언어 검수가 통과하고 증거가 연결되는 것이다.
검증 환경은 이 Mac의 비공개 웹 후보본이다. 예상 1~2인일.

## 먼저 검토할 화면

탐방 기본 화면의 버튼 수, 오른쪽 패널의 폭, 모바일 하단 패널의 높이, 신청 단계와 일정 표시 크기를 먼저 검토한다. 색·글꼴·아이콘·간격은 화면 구조 검토 뒤 다듬는다. 시안의 샘플 데이터는 출시 정책을 확정하지 않는다.
